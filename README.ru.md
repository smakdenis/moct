# moct

**Превратите идею в задание, по которому другая модель сможет выполнить работу.** moct помогает выбранной модели разработать выразительный замысел, перевести его в самодостаточный промпт с критериями приёмки и подобрать исполнителя. После этого делает паузу для переключения модели, чтобы вы контролировали расход на подготовку и реализацию. Работает в **Codex, DeepSeek Harness и Kimi Code**.

## Первый запрос

| Где вы работаете | Что написать |
| --- | --- |
| Codex | `Сделай промпт для …` или `$moct:moct Сделай промпт для …` |
| DeepSeek Harness | `/moct Сделай промпт для …` |
| Kimi Code | `/skill:moct Сделай промпт для …` |

Например, **«Сделай промпт для каталога выездной библиотеки. У книги может быть ноль экземпляров, а иногда остаток неизвестен. Читатель должен видеть разницу»**. Укажите формат результата и нужные вложения. Назовите среду исполнения, если хотите перейти в одну из двух других.

Даже на запрос в одну строку автор готовит подробное задание. Ориентир для копируемого блока — **8 000–12 000 знаков без пробелов**, минимум **6 000**. Внутри будут замысел, конкретные решения, последовательность работы, примеры и условия приёмки. При доработке вы получите полную обновлённую версию. «Сделай промпт для слогана из трёх слов» сохраняет подробный бриф. «Сам промпт до 500 знаков» задаёт свой предел. «Только промпт» убирает рекомендацию после блока.

В том же чате выберите рекомендованную модель и напишите **«продолжай»**. В Kimi Code селектор открывается командой `/model`. При переходе между приложениями откройте новый чат у исполнителя, вставьте целиком блок задания и приложите названные файлы. Для обычного приложения Kimi это и есть способ передачи. Нативная команда `/skill:moct` относится к Kimi Code. [Команды Kimi Code](https://moonshotai.github.io/kimi-code/en/reference/slash-commands.html)

Если выбранная модель уже совпадает с рекомендованной и вы хотите продолжить в ней, напишите **«продолжай в текущей модели»**. Во время проверки Luna предложила выбрать саму себя. Сверка названия в селекторе и эта явная команда решают такой случай.

## Как выбор влияет на лимиты

Автор расходует лимит выбранной авторской модели. Реализация и её проверка расходуют лимит модели, в которой вы их запустили. Если весь чат продолжает работу на Astra, её координация тоже расходует лимит. Для экономии заканчивайте авторский ход на готовом промпте и переключайте весь чат. При разных провайдерах действует тариф соответствующего аккаунта.

moct учитывает инструменты, сложность задачи, видимые модели и сопоставимые цены. В Codex он запрашивает текущий каталог, учитывает дату кэша и поддерживаемый уровень рассуждения. В DeepSeek Harness важны модели выбранного профиля, в Kimi Code — модели текущей сессии. Если сведений о личном тарифе не хватает, рекомендация указывает основание выбора и неизвестную часть стоимости. [Модели Codex](https://learn.chatgpt.com/docs/models?surface=app) · [Тарифы Codex](https://learn.chatgpt.com/docs/pricing)

## Как moct учитывает ошибки

Если результат разошёлся с промптом, попросите **«Разбери, где пришлось додумывать»**. moct проверит, какого требования не хватало, какое уже было записано и какие проверки оказались недоступны. Исправление для следующих задач можно сохранить явной просьбой.

> Запомни в moct для задач с данными. Когда пропуск и нулевой остаток имеют разный смысл, включай в приёмку два примера. В одном ожидается число 0, во втором — null.

При следующей похожей задаче модель сможет включить эту проверку в промпт. Запись хранится в личном файле `~/.moct/lessons.sqlite3` и содержит область, условие и проверку. Три приложения на одном компьютере читают один профиль при наличии разрешений и Python. Команды **«Покажи правила moct»** и **«Забудь правило с ID …»** дают контроль над ним. Для другого устройства или обычного чата Kimi скопируйте нужное правило вместе с заданием. Автоматической отправки в общий архив пользователей нет.

## Установка из архива

Распакуйте архив и откройте терминал в папке `moct`, где лежит этот README. Для Codex используйте штатный менеджер плагинов или `install.command` на macOS.

```bash
codex plugin marketplace add "$PWD" --json
codex plugin add moct@moct --json
```

При первой установке нативных обработчиков или запросе доверия после обновления откройте Review hooks в Codex или `/hooks` в его CLI. Подтвердите оба обработчика moct. Первый распознаёт запрос и продолжение. Второй при обычной передаче проверяет длину копируемого блока и подсказку о переключении. Если ответ слишком короток, он может один раз попросить автора раскрыть задание. В Harness и Kimi проверку полноты выполняет сама модель по инструкции.

Для DeepSeek Harness и Kimi Code нужен Python 3. В Windows команду `python3` может заменять `py -3`. Запустите строку для нужной среды.

```bash
python3 install_skill.py deepseek
python3 install_skill.py kimi
```

Установщик кладёт навык `moct` в `skills/` внутри `DSH_HOME` или `KIMI_CODE_HOME`. Обычно это `~/.dsh/skills/moct` и `~/.kimi-code/skills/moct`. Для установки только в одном проекте добавьте `--project /путь/к/проекту`. Уже установленная идентичная копия распознаётся. При совпадении имени с другим содержимым установщик сообщит путь к конфликту. Откройте новую сессию клиента для проверки команды. [Навыки DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md) · [Навыки Kimi Code](https://github.com/MoonshotAI/kimi-code/blob/main/docs/en/customization/skills.md)

Чтобы обновить прежнюю версию в Harness или Kimi, перенесите установленную папку `skills/moct` в резервное место вне `skills/`, повторите установку для нужного клиента и откройте новую сессию.

## Что означает пауза

В Codex доверенный обработчик может заблокировать типовое «продолжай» на прежней модели ещё до нового модельного хода. Для этого нужна сохранённая отметка о предыдущем запросе в том же чате. Она содержит идентификатор модели, время и признаки формата и объёма. Имя файла образовано из хеша идентификатора чата. Отметка действует до семи дней и очищается после постороннего запроса. При запрете записи, пропуске обработчика или другой формулировке проверка может не сработать. Для двухэтапного сценария первым запросом попросите подготовить промпт. В Harness и Kimi автор завершает ответ по инструкции, а пользователь выбирает следующий чат.

В комплекте есть [переносимый текст для чата Kimi](plugins/moct/skills/moct/references/moct.md) и [отчёт о проверках](VERIFICATION.md). Проверки пакета запускаются командой `python3 -B -m unittest discover -s tests -v`. Все три среды используют собственный чат. [Apps SDK UI](https://github.com/openai/apps-sdk-ui)

## Переход с most

Установите `moct@moct`, отключите прежний `most@most` в Codex и подтвердите оба новых обработчика moct. В Harness и Kimi Code после установки `skills/moct` перенесите прежнюю папку `skills/most` за пределы каталога навыков.

При первом обращении помощник правил скопирует прежний профиль `~/.most/lessons.sqlite3` в `~/.moct/lessons.sqlite3` с сохранением идентификаторов. Прежний файл остаётся резервной копией. Если профиль moct уже существует, используется он.
