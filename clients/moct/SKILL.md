# moct

Прочитай [порядок авторства, передачи и разбора](references/moct.md). При создании и доработке промпта выполни оба авторских этапа в текущей модели за один ход. Внутри самого копируемого блока дай 8 000–12 000 знаков без пробелов, минимум 6 000, даже если запрос короткий. Явный лимит самого промпта имеет приоритет. При доработке выдай полную версию. Перед отправкой проверь объём и содержательность блока по разделу «Глубина промпта для исполнителя». В обычном финальном ответе после блока дай рекомендацию и действие для пользователя. При просьбе «только промпт» заверши ответ на блоке. Здесь отвечай на языке запроса. Используй [ориентиры по видам результата](references/implementation-handoff.md) для предметных деталей и примеров.

moct поддерживает три среды. По умолчанию выбирай подходящую модель из доступных в текущей среде. Если человек выбирает между средами, сравни доступные варианты из этой тройки по возможностям задачи и сопоставимым единицам оплаты. Учитывай список именно этой учётной записи и актуальные официальные условия. У подписки, API и локального тарифа могут быть разные единицы. При неизвестной цене назови необходимую возможность и что известно о расходе. Любая передача начинается отдельным действием пользователя.

Если приложение вернуло управление автору для служебной проверки, после неё снова помести весь готовый блок и предусмотренную рекомендацию в последнее сообщение.

- **DeepSeek Harness.** Используй список моделей текущего профиля Harness. Предложи пользователю выбрать модель чата в интерфейсе и отправить «продолжай». При передаче сюда из другой среды достаточно открыть чат Harness, вставить готовый блок и приложить перечисленные материалы.
- **Kimi.** В Kimi Code список и выбор модели текущей сессии доступны через `/model`. Новый запрос к навыку можно начать с `/skill:moct`. В обычном чате Kimi пользователь может вставить готовый блок с вложениями.
- **Codex.** Для авторства в Codex есть нативный навык `$moct:moct`. Для реализации достаточно вставить блок в чат на выбранной модели. При продолжении в том же чате Codex может проверить выбранную модель через свой доверенный обработчик.

В DeepSeek Harness и Kimi пауза действует как инструкция автору. Удостовериться в переключении можно по сведениям клиента или явному подтверждению пользователя. Не запускай подчинённую модель и не инициируй запрос в другую среду за пользователя.

## Поправки для следующих задач

Если доступен Python, перед новым промптом прочитай подходящие правила с помощью `python3 scripts/lessons.py list --scope data` из каталога этого навыка. Области — `data`, `code`, `interface`, `writing`, `visual`, `other`, `general`. Применяй проверку только при совпадении условия. Новая инструкция пользователя важнее записи. Если данных нет, продолжай работу.

После фактической проверки помоги отделить упущение в задании от ошибки исполнителя или отсутствующего инструмента. По просьбе «запомни для похожих задач» сохрани короткие поля `when` и `check` через UTF-8 JSON на stdin команды `python3 scripts/lessons.py save --scope data`. Назови полученный ID. Для просмотра есть `list`, для удаления конкретного правила по просьбе человека — `forget ID`. На одном компьютере три среды могут читать общий пользовательский файл `~/.moct/lessons.sqlite3`, когда у них есть доступ. На другом устройстве или в чате без файлов передай одобренное правило текстом.
